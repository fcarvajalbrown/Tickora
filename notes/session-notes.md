- Phase 1 (PRD section 11, step 1) built: Cargo workspace, `crates/tickora-core`, zero dependencies. Modules: `rng` (PCG32, matches the reference vector for seed 42 stream 54), `hash` (FNV-1a 64, little-endian writers, matches reference vectors), `input` (tick-indexed `InputLog`, versioned little-endian binary format `TKIL` v1, strict parse errors), `sim` (`Sim` trait, `Runner`, chained `ReplayHash`, `run_with` per-tick callback, `first_divergence`).
- Tests: 16 unit tests and 9 replay tests, including 300 fuzzed input logs and a pinned golden hash (`238730705328002493` for seed 0xC0FFEE, 600 ticks). Passed on Windows local (debug and release) and in CI on windows-latest and ubuntu-latest (debug and release), run 40532173793. The golden value comes from this implementation, so it guards against regressions and platform drift, not against a wrong algorithm.
- The core avoids the three HPL3 problems by construction: no clock anywhere, the tick is an integer counter, the input log is addressed by tick so there is no catch-up cap and no dropped backlog. A wall-clock driver, when one exists, must live outside the core and only decide how many ticks to request.
- Rules the toy sim in `tests/replay.rs` follows and real sims must too: integer or fixed-point state only in hashed data, no HashMap iteration order, no threads inside `step`, all randomness through the `Rng` passed in.

- MCP spec finding (modelcontextprotocol.io, fetched this session): the latest revision is 2026-07-28 and is stateless, with no `initialize` handshake; every request carries protocol version and client capabilities in `_meta`, and servers must implement `server/discover` and return `UnsupportedProtocolVersionError` (code -32022) with a `supported` list. The legacy revisions (2025-11-25 and earlier) use `initialize`. stdio is newline-delimited JSON-RPC. Tool results carry `resultType: complete`, `content`, optional `structuredContent` and `isError`; tool names use letters, digits, underscore, hyphen, dot. Decided for the MCP server: new `tickora-mcp` crate with `serde` and `serde_json` only, and tools step, state hash, list components, query, get entity, reset.
- Core introspection built for the MCP layer (commit d6d64a9, CI run 40542296724 passed): `Component::fields()` returns `(name, FieldValue)` pairs (`Int`, `Bool`, `Fx`, `Text`), `World::describe(entity)` lists present components in registration order, `World::query_names(&[names])` intersects named stores and returns entities in the smallest store's dense order, `EcsError` gained `UnknownComponent` and is no longer `Copy`. 55 unit tests, 9 replay, 5 ECS pass in debug and release.
- MCP server built in `crates/tickora-mcp` (commits 4a5c4cc to a7842cc), dependencies `serde` and `serde_json` only (no derive feature; transitive: serde_core, itoa, memchr, zmij). Modules: `jsonrpc` (parse, success, failure, error codes), `server` (`Server<H: Host>`, `serve` generic over `BufRead` and `Write`, one message per line, blank lines skipped, invalid UTF-8 and bad JSON answered with -32700, notifications and client responses never answered, exit on EOF), `host` (`Host` trait), `tools` (the six tools), `demo` (`Arena`, `Command`, `ArenaHost`, same arena as `tickora-core/tests/ecs.rs`), and a `tickora-mcp` binary that serves the demo arena on stdio with seed 0.
- Era routing: a request whose `_meta` has `io.modelcontextprotocol/protocolVersion` is served modern (version must be `2026-07-28`, else -32022 with `supported` listing modern and legacy versions and `requested`; missing `clientCapabilities` is -32602; results carry `resultType: complete` and `_meta` serverInfo). Without it, `initialize` selects legacy for the process (known versions 2025-11-25, 2025-06-18, 2025-03-26, 2024-11-05 are echoed, anything else gets 2025-11-25); any other method before `initialize` is -32602. `ping` works in both.
- Tool outputs: hashes and the seed are decimal strings because u64 above 2^53 loses precision in JavaScript clients; `tickora_reset` takes the seed as an integer or a decimal string. `tickora_step` applies `inputs` on the first stepped tick only, validates every input before applying any (a bad input leaves tick and hash unchanged), caps `ticks` at 100000. Unknown arguments are rejected. Tool failures (bad input, unknown component, dead entity) are `isError: true` results; an unknown tool name is JSON-RPC -32602. Fx fields print via `to_f64`, so 1.2 shows as 1.1999999999534339 (Q32.32 cannot hold 0.1 exactly); this is derived output only.
- MCP tests: 14 unit and 9 session tests drive the whole loop in-process: identical transcripts for the same seed and call sequence, modern and legacy eras reach the same hashes, different seeds diverge, MCP hashes equal a direct `Runner<Arena>` fed the same input log, reset with seed u64::MAX equals a fresh run, and a pinned session hash (state `5353186769580955786`, replay `8908456892389666548` for script seed and sim seed 0xC0FFEE, 400 calls; the value comes from this implementation). Debug and release pass locally; CI run 40544595848 passed on windows-latest and ubuntu-latest.
