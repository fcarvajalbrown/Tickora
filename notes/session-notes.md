# Session notes

Current state:
- Repo is public at github.com/fcarvajalbrown/Tickora with README, description and 10 topics.
- Bunker binary fully decompiled into `research-private/bunker/decompile/code/`, one file per function address; pyghidra-mcp indexes are built, server ready in about a minute.
- Bunker main loop and tick answered in `research-private/bunker/NOTES.md`, "Main loop and tick": constant dt, but steps per frame come from wall time, catch-up cap and backlog drop, which is where determinism breaks.
- Phase 1 (PRD section 11, step 1) built: Cargo workspace, `crates/tickora-core`, zero dependencies. Modules: `rng` (PCG32, matches the reference vector for seed 42 stream 54), `hash` (FNV-1a 64, little-endian writers, matches reference vectors), `input` (tick-indexed `InputLog`, versioned little-endian binary format `TKIL` v1, strict parse errors), `sim` (`Sim` trait, `Runner`, chained `ReplayHash`, `run_with` per-tick callback, `first_divergence`).
- Tests: 16 unit tests and 9 replay tests, including 300 fuzzed input logs and a pinned golden hash (`238730705328002493` for seed 0xC0FFEE, 600 ticks). Passed on Windows local (debug and release) and in CI on windows-latest and ubuntu-latest (debug and release), run 40532173793. The golden value comes from this implementation, so it guards against regressions and platform drift, not against a wrong algorithm.
- The core avoids the three HPL3 problems by construction: no clock anywhere, the tick is an integer counter, the input log is addressed by tick so there is no catch-up cap and no dropped backlog. A wall-clock driver, when one exists, must live outside the core and only decide how many ticks to request.
- Rules the toy sim in `tests/replay.rs` follows and real sims must too: integer or fixed-point state only in hashed data, no HashMap iteration order, no threads inside `step`, all randomness through the `Rng` passed in.

Open:

- Floats: decided, fixed-point in hashed state, f32 only for derived output (rendering, MCP output), never written back into hashed state; gameplay code uses a typed fixed-point wrapper with operator overloads. Recorded as ADR 0001 (i64, 32 fractional bits, i128 intermediates). Corpofobia (Godot, GDScript floats) shows the agentic workflow working well; it has no cross-machine replay-hash requirement, so it does not argue for floats in Tickora's hashed state.
- ECS built (`ecs` module: `Entity` index plus generation, LIFO free list, one `SparseSet` per component, explicit `Component` trait with `NAME` and `hash_into`, `World` with `register`, `spawn`, `despawn`, `insert`, `remove`, `get`, `get_mut`, `query`, `query_mut`, `query2`, `component_names`, `state_hash`). Components are hashed in registration order; stale handles are rejected; iteration is dense order. Not done: a derive macro (needs a dependency decision), systems or schedules, `query3` and above, the trig tables ADR 0001 calls for.
- `fx` module built per ADR 0001: saturating arithmetic (never wraps, so debug and release agree), i128 intermediates, divide by zero saturates by sign, `sqrt` is the exact floor root, `to_f32` and `to_f64` are for derived output only.
- Tests now: 53 unit, 9 replay, 5 ECS (replay equality, log round trip, divergence, pinned hash `9281879666421455162` for seed 0xC0FFEE and 600 ticks, and a 5000-operation fuzz against a BTreeMap model). Debug and release pass locally on Windows; CI run 40540600776 passed on windows-latest and ubuntu-latest. The pinned value comes from this implementation.

- MCP spec finding (modelcontextprotocol.io, fetched this session): the latest revision is 2026-07-28 and is stateless, with no `initialize` handshake; every request carries protocol version and client capabilities in `_meta`, and servers must implement `server/discover` and return `UnsupportedProtocolVersionError` (code -32022) with a `supported` list. The legacy revisions (2025-11-25 and earlier) use `initialize`. stdio is newline-delimited JSON-RPC. Tool results carry `resultType: complete`, `content`, optional `structuredContent` and `isError`; tool names use letters, digits, underscore, hyphen, dot. Which era Claude Code speaks is not yet checked. Decided for the MCP server: new `tickora-mcp` crate with `serde` and `serde_json` only, and tools step, state hash, list components, query, get entity, reset.
