# Session notes

Current state:
- Repo is public at github.com/fcarvajalbrown/Tickora with README, description and 10 topics. CI (fmt, clippy, tests in debug and release) is green on windows-latest and ubuntu-latest, last run 40551169613 at ae5f90a.
- PRD phases 1, 2 and 3 are done. Phase 3 followed Felipe's choices: JSON format, all four assertion kinds (hashes, entity and component counts, query match counts, field values with Fx as raw or approx with tolerance), and both a CLI and an MCP tool. The format is specified in `docs/scenarios.md`. Out of scope so far: a record mode that writes expected values, scenarios for non-arena sims, screenshot assertions.
- `crates/tickora-mcp/src/scenario.rs`: `load`, `parse`, `from_json` (strict, unknown keys rejected, ticks validated, cap `MAX_RUN_TICKS` 1,000,000) and `run<H: Host>` (resets the host, evaluates every assertion, outcomes in file order, `Report::to_json`). Inputs the host rejects are a scenario error, not a failed assertion.
- CLI: `tickora-mcp scenario [--json] <file>...` runs each file on a fresh `ArenaHost`, exit 0 pass, 1 failed assertion, 2 malformed or unreadable. No arguments still serves MCP on stdio, so `.mcp.json` is unchanged.
- MCP tool 7, `tickora_run_scenario`: exactly one of `path` (relative to the server's working directory) or inline `scenario`; runs on `Host::fresh(seed)`, a new trait method, so the live sim is untouched. A failed assertion is `isError: false` with `passed: false`.
- `scenarios/arena.json` (16 assertions, seed 0xC0FFEE, 600 ticks, pins state `17906231570684560215` and replay `17151601846166727076`) and `scenarios/arena-wrong-expectations.fail.json`; files ending `.fail.json` must fail. The 12 hand-derived count and hp assertions passed on the first run; hashes and the Fx raw value were pinned from the implementation.
- While a Claude Code session runs the `tickora` server, `target/release/tickora-mcp.exe` is locked and `cargo test --release` cannot relink it (os error 5). Run local release tests with `CARGO_TARGET_DIR=target/verify` instead of killing the server.
- `crates/tickora-core`, zero dependencies: `rng` (PCG32), `hash` (FNV-1a 64), `input` (tick-indexed `InputLog`, binary format `TKIL` v1), `sim` (`Sim` trait, `Runner`, chained `ReplayHash`, `first_divergence`), `fx` (ADR 0001: i64 Q32.32, saturating, i128 intermediates, `to_f32`/`to_f64` for derived output only), `ecs` (sparse sets, generational `Entity`, `Component` with `NAME`, `hash_into` and `fields`, `World` with `describe` and `query_names`, components hashed in registration order).
- `crates/tickora-mcp`, dependencies `serde` and `serde_json` only (no derive feature): `jsonrpc`, `server` (`Server<H: Host>`, newline-delimited stdio generic over `BufRead` and `Write`, exit on EOF), `host` (`Host` trait), `tools`, `demo` (`Arena`, `Command`, `ArenaHost`), and a `tickora-mcp` binary serving the demo arena with seed 0.
- Both MCP eras are served. A request whose `_meta` carries `io.modelcontextprotocol/protocolVersion` is handled as 2026-07-28: -32022 with `supported` and `requested` for other versions, -32602 without `clientCapabilities`, results carry `resultType: complete` and serverInfo in `_meta`, and `server/discover` and `tools/list` carry `ttlMs: 3600000` and `cacheScope: public`. Without it, `initialize` selects legacy (2025-11-25, 2025-06-18, 2025-03-26, 2024-11-05 echoed, anything else gets 2025-11-25); other methods before `initialize` are -32602.
- Tools: `tickora_step` (inputs on the first stepped tick only, all inputs validated before any applies, ticks 1 to 100000), `tickora_state_hash`, `tickora_list_components`, `tickora_query` (limit default 100), `tickora_get_entity`, `tickora_reset` (seed as integer or decimal string). Hashes and seeds are decimal strings, because u64 above 2^53 loses precision in JavaScript. Unknown arguments are rejected; tool failures are `isError: true`; an unknown tool is -32602. Fx fields print via `to_f64` (1.2 shows as 1.1999999999534339).
- Claude Code 2.1.311 is a dual-era client: it probes `server/discover` first and falls back to `initialize` only on method-not-found or silence. Against tickora-mcp it uses the modern era, confirmed live (`protocolEra: modern` in a headless debug log). Registered with one command, `claude mcp add -s project tickora -- cargo run -q --release -p tickora-mcp`, into the committed `.mcp.json`. Build the release binary before the first connect, or compiling eats into the 60 s connect timeout.
- Tests: core 55 unit, 9 replay, 5 ECS; MCP 26 unit, 4 scenario, 10 session. Pinned values come from this implementation, so they guard against regressions and platform drift, not a wrong algorithm: replay `238730705328002493` (seed 0xC0FFEE, 600 ticks), ECS `9281879666421455162` (seed 0xC0FFEE, 600 ticks), MCP session state `5353186769580955786` and replay `8908456892389666548` (script and sim seed 0xC0FFEE, 400 calls).
- Rules every sim follows: integer or fixed-point state only in hashed data, no HashMap iteration order, no threads inside `step`, all randomness through the `Rng` passed in, no clock in the core (a wall-clock driver lives outside and only decides how many ticks to request).
- Bunker main loop and tick answered in `research-private/bunker/NOTES.md`; the decompile and pyghidra-mcp indexes are built.

- Phase 4 (screenshot capture, wgpu offscreen per PRD section 6) is in progress, deciding before code. Decided:
  - Dependencies approved by Felipe: wgpu 30.0.1 with default features off (dx12, vulkan, wgsl, std), png 0.18.1, pollster 1.0.1, all MIT OR Apache-2.0. wgpu 30 needs Rust 1.87, so workspace `rust-version` goes from 1.85 to 1.87.
  - Screenshot result, chosen by Felipe: always an MCP image block (base64 PNG) plus structured metadata (tick, state hash, width, height, PNG hash); an optional `path` argument also writes the PNG to disk.
  - Camera, chosen by Felipe under the CLAUDE.md rule to copy Unreal where it does not collide with the PRD: Unreal's viewport model as tool arguments, no window (an interactive fly camera would be the editor PRD section 7 rules out). `viewport` named after `ELevelViewportType`, top orthographic by default for the 2D arena, plus `location` and `ortho_width`; every result carries a BugIt-style camera string that can be passed back to reproduce the view, as BugItGo does.
  - Drawing, chosen by Felipe: `view_mode` named after Unreal's, `unlit` (default, each entity a filled 4-unit square coloured by hp, red at 0 to green at 100) or `wireframe` (outlines only); `show_grid` flag on by default.
  - Golden comparison, chosen by Felipe: Unreal's screenshot comparer model. Presets zero, low, medium, high, custom; per-channel tolerance, max local error over chunks, max global error, ignore-anti-aliasing neighbour search. Goldens bucketed by platform and backend (Unreal buckets by Platform_RHI_ShaderModel) with alternatives allowed, written only by an explicit record flag (Unreal's Add New and Replace). Unreal's public docs give no preset numbers, so ours are measured on the CI software adapters and recorded.
  - CI adapter, chosen by Felipe: pinned software adapters. Linux downloads Mesa 26.1.3 lavapipe (`mesa-26.1.3-linux-x86_64.tar.xz` from gfx-rs/ci-build release build29, the one wgpu's own CI uses) and points `VK_DRIVER_FILES` at a written `icd.json`; Windows uses the built-in DX12 WARP through wgpu's fallback adapter, and if that is missing or too old on the runner, stop and bring Felipe the NuGet WARP route. Goldens are recorded from these adapters.
